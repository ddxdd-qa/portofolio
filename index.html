Bug ID: BUG-SW-189 · Jira / GitLab Defect

Race Condition on Concurrent "Double-Tap" Transfer Button Leads to Duplicate Deduction

Severity: S1 Critical Priority: P1 High Component: Wallet API / Mobile Resolution: Verified in Staging
Environment
Staging v2.4.1 · Android Build #2026.08.30
Network Profile
Throttled 3G (350ms RTT latency)
Reporter
Dedy Blinda Rosandy (Senior QA Tester)
Risk Impact
Double spend / Financial Ledger discrepancy

Steps to Reproduce:

  1. Log into StarWALLET account with balance IDR 500,000.
  2. Configure network proxy to simulate slow 3G latency (350ms).
  3. Initiate a transfer of IDR 100,000 to contact USR-39211.
  4. On the confirmation sheet, rapidly double-tap the "Confirm & Pay" button within ~180ms.
  5. Inspect wallet balance and transaction ledger records.
Actual Behavior (Defect):

Two parallel HTTP POST requests fired to /api/v1/wallet/transfer. Both requests returned 200 OK. Sender was charged IDR 200,000 instead of IDR 100,000.

Expected Behavior:

Client-side debounce must prevent multiple clicks. Server-side idempotency key (X-Idempotency-Key) must reject duplicate calls with 409 Conflict.

Server Proxy Evidence Log:

POST /api/v1/wallet/transfer [200 OK] (TxID: TX-99014A) - 14:02:11.104 POST /api/v1/wallet/transfer [200 OK] (TxID: TX-99014B) - 14:02:11.238 WARN: Concurrent balance modification detected on wallet W-84920 without active Redis distributed lock.
